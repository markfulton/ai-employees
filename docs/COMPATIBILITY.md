## How a row becomes tested

A row becomes `tested` only with three results, each with evidence you can open: an install result (the installer or plugin install exited 0 and the kit's CONTRACT.md is on disk), a first routine result (a runlog record with status ok or partial from that harness on that OS), and a scheduled run result (runlog records from the scheduler, counted per routine over a stated window). Until all three exist the row stays `documented` or `partial`. A `--help` answer, a CLI on the path or a repository document alone never produces `tested`.
