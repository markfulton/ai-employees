## How a row becomes tested

Three results, each with evidence that can be pointed at, and they stay separate results rather than one judgement.

1. An install result. The installer exits 0 into a folder outside any sync service and that folder holds the kit CONTRACT.md. The evidence is the command, the exit code and the path.
2. A first routine result. A run record exists for that kit with status ok or partial. The evidence is the routine id, the timestamp and the line in the run log.
3. A scheduled run result. Run records exist across days from a registered schedule, not from a hand invocation. The evidence is the counts of ok, partial and failed by routine id over a stated window.

The browser lane is tested only when a routine whose schedule marks it browser capable recorded ok inside the last 14 days. A help screen, a version string or a file read is never evidence for any of the four columns.

Today one row is tested on all four columns, the GTM Engineer on Claude Code on Windows, because it is the only kit with a live installation and a run log on this machine. Seven rows carry a tested install and nothing further, because the installer was actually run for them and no routine was. Everything else is documented.
